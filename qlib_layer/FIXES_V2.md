## 一、① 修复权：实测后修正六家的一个判断

### 六家都说应该用 hfq，但实测证明 qfq 才对

**除权日当天（茅台 2024-06-19，已知分红日）：**

| 口径 | 2024-06-18 → 06-19 | 说明 |
|---|---|---|
| 不复权 | 1521.50 → 1501.00（**-1.35%**） | 含除权假跌 |
| **前复权** | 1387.16 → 1397.54（**+0.75%**） | 修正了跳空 |
| 后复权 | 9609.93 → 9668.33（**+0.61%**） | 也修正了 |

**跨除权日 20 日动量（工商银行）：**

| 口径 | mom20 |
|---|---|
| 不复权 | +14.18% |
| **前复权** | **+17.70%** ← 消除假跌，最接近真实 |
| 后复权 | +8.51% ← **反而更低，不符合预期** |

**结论：qfq（前复权）是正确选择，六家说 hfq 更好是错的。**

理由：hfq 以发行价为锚，早期价格会被放大（茅台 hfq 首价 10792 vs 真实 1750），
除权日的比例误差被放大；qfq 以最新价为锚，近期价格与真实一致。

## 二、② 自动防线：彻底重做

### 核心改动：因子定义抽成唯一真源

**新文件 `qlib_layer/factors.py`**：

```python
FACTOR_EXPRESSIONS = {
    "rev1": "Ref($close, 1) / $close - 1",
    "mom5": "$close / Ref($close, 5) - 1",
    "mom20": "$close / Ref($close, 20) - 1",
    "vol20": "Std($close, 20) / Mean($close, 20)",
    "vol_ratio": "Mean($volume, 5) / Mean($volume, 20)",
    "dev20": "($close - Mean($close, 20)) / Mean($close, 20)",
}
DEFAULT_WEIGHTS = {...}
FACTOR_DIRECTION = {...}
```

**`run.py` 和 `validate.py` 都从这里导入。** 改这里 = 同时改生产代码和被校验对象，无法再各自漂移。

### 防线 1：方向断言跑真实 Qlib 引擎

**关键**：不再用 numpy 参照实现自证，而是：
1. 构造合成行情（涨 20% / 跌 20% / 平坦）
2. 灌进临时 Qlib 格式
3. **用 `D.features` 算**（真实表达式引擎）
4. 验证方向 + **精确值**

```
✅ rev1 方向（Qlib 引擎）      涨 -0.0043（应<0）/ 跌 +0.0064（应>0）
✅ mom5 方向（Qlib 引擎）      涨 +0.0218（应>0）/ 跌 -0.0311（应<0）
✅ mom20 方向（Qlib 引擎）     涨 +0.0935（应>0）/ 跌 -0.1136（应<0）
✅ vol20 方向（Qlib 引擎）     平坦序列 0.00000000（应≈0）
✅ vol_ratio 方向（Qlib 引擎）  量能恒定 1.00000000（应≈1）
✅ dev20 方向（Qlib 引擎）     涨 +0.0423（应>0）/ 跌 -0.0574（应<0）
✅ mom20 精确性（构造 +20% -> 0.2）      实际 +0.200000
✅ vol20 精确性（窗口必须=20）            实际 0.022249
✅ vol_ratio 精确性（分子分母不可颠倒）    实际 1.600000
```

### 精确性校验怎么构造

**vol20**：用 `[100×19, 110]` 序列
- mean = 100.5
- std(ddof=1) = 2.236068
- vol20 = 0.022249

**vol_ratio**：用 `[1e6×35, 2e6×5]`
- 5 日均量 = 2e6
- 20 日均量 = 1.25e6
- vol_ratio = 1.6（颠倒就是 0.625）

## 三、过程中发现的两个新 bug

### bug 1：Qlib 的 Std 用 ddof=1，不是 ddof=0

**现象**：vol20 精确性校验失败，实际 0.022249 vs 期望 0.021686（差 2.6%）。

**原因**：`np.std()` 默认 ddof=0（总体标准差），Qlib 的 `Std()` 用 ddof=1（样本标准差）。

**影响**：`factors.py` 的参照实现也错了，会让参照值与 Qlib 值系统性偏离 2.6%。

**已修**：两处都改成 `ddof=1`。

**这个 bug 之前从没被发现**，因为第一版防线不比对具体数值。

### bug 2：合成数据的代码前缀

**现象**：防线报"Qlib 表达式引擎无输出"。

**原因**：`dump_to_qlib` 会给代码加交易所前缀（`600001` → `SH600001`），
但 `validate.py` 用原始代码去 `D.features` 查。

**已修**：查询时用 `SH` 前缀。
