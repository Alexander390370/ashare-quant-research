## 一、新闻的 point-in-time ✅ 已补

### 问题

新闻本身带发布时间，但不同 vendor 的过滤行为不一致：

- 我们自己的 AKShare vendor（`akshare/news.py`）**已按 `发布时间` 过滤** ✅
- Yahoo 的 news vendor 依赖 API 区间参数，**不保证逐条裁剪** ⚠️

对历史日期回测，只要有一条"未来新闻"混进来，分析师就可能做出当时不可能做出的
判断 —— 这是前视偏差。

### 解法

新增 `tradingagents/dataflows/vendors/akshare/news_pit.py`，在 `get_news` 工具
**出口做统一兜底裁剪**。不管上游 vendor 做没做，出口保证干净。

处理策略（按条目块）：

```
用 ### 或 "N. " 切块
  → 每块在前 6 行里找第一个日期 token
  → 晚于截止日 → 整块删除
  → 找不到日期 → 保留（宁可多留，不可错删）
```

支持的日期格式：`2026-10-20` / `2026/10/20` / `2026年10月20日`。

### 验证

```

截止 2026-10-27：全部保留 ✅
```

## 二、② 样本量 —— 缓解手段：批量网格脚本

### 这是成本问题，不是正确性问题

本机实测：**1 个单元格（只跑 market）≈ 27 分钟**。

| 目标样本 | 只技术面 | 全分析师 |
|---|---|---|
| n=20 | ~9 小时 | 数天 |
| n=50 | ~23 小时 | 一周以上 |

### 新增工具：`tools/run_backtest_grid.py`

解决挂机跑的三个痛点：

**1. 断点续跑**——中断后用同一个 `--run-id` 接着跑，已完成单元格自动跳过

```powershell
python tools\run_backtest_grid.py --tickers 600519.SS,000001.SZ `
  --start 2026-06-01 --end 2026-09-01 --every 7 `
  --analysts market --run-id night01
```

**2. 成本预警**——开跑前估算总耗时，超过 1 小时要求确认

```
单元格数  : 2 × 14 = 28
预计耗时  : 约 12.6 小时（单格实测估算）
⚠️  预计超过 1 小时。建议先跑 2 格验证链路：--every 30 --analysts market
   确认要继续，加 --yes 重跑本命令。
```

**3. 进度可见 + 自动汇总**

```
[23:15:02] 第 3/28 格  600519.SS 2026-06-15  | 上一格 26 分钟  | 预计剩余 10.8 小时
```

跑完自动输出按评级分组的 `hit_rate` / `mean_alpha`。

**只汇总不跑**：

```powershell
python tools\run_backtest_grid.py --summarize night01
```

### 诚实的判断

**堆样本量的收益可能不如直接上传统量化。** 以 27 分钟/格算，n=50 是一周的计算。
如果目标是统计上可信的策略验证，LLM 多智能体不是合适工具——该用 Qlib 一类。

这个脚本的价值是"让挂机变得可行且可控"，不是"让 LLM 变成量化引擎"。

## 三、④ LLM 非确定性 —— 缓解手段：多采样取共识

### 为什么不能根除

三个独立来源：

1. **模型采样**：即使 `temperature=0`，provider 也不保证逐字节一致；思考型模型
   （deepseek-v4-pro）波动更大，因为**推理过程本身在采样**
2. **实时数据漂移**：新闻、社交情绪每次拉到的内容不同
3. **不归档 text feeds**：上游明确写 *"text feeds are not archived"*

第 3 点是设计取舍不是 bug——归档全部文本会让磁盘爆炸。

### 新增模块：`tradingagents/consensus.py`

同一 (标的, 日期) 跑 N 次，取评级众数，并报告**一致率**与**分歧分布**。

```python
from tradingagents.consensus import run_consensus

result = run_consensus(graph, "600519.SS", "2026-09-01", samples=3)
print(result.describe())
```

输出示例：

```
## 600519.SS 2026-09-01 多采样共识（n=3/3）

- **众数评级**：Underweight
- **一致率**：100%
- **方向稳定**：是
- **分布**：Underweight×3

解读：多次采样完全一致，该判断对此模型稳定。
```

分歧时：

```
- **一致率**：33%
- **方向稳定**：否（存在方向分歧）
- **分布**：Buy×1, Sell×1, Hold×1

解读：**分歧显著**。这本身就是信息——该判断不稳健，不宜据此下注。
```

### 设计要点

| 决策 | 理由 |
|---|---|
| **并列时取方向最中性的** | 避免虚假的方向性结论。Buy/Hold 并列 → 取 Hold |
| **默认不开启** | 成本 N 倍，只在关键决策上用 |
| **N=3 是建议值** | 最小有统计意义的配置；不超过 5 |
| **单次失败不中断** | 记录到 `errors`，其余采样继续 |

### 这个方法的真正价值

**一致率低本身就是有价值的信息。** 它告诉你"这个标的/时点处于模糊地带"，
比单次结果更诚实。单次跑出 Buy 你不会怀疑；3 次跑出 Buy/Sell/Hold 你就知道
这个判断不可靠。

### 另外两条缓解（已配置）

**降低 temperature**：

```ini
TRADINGAGENTS_TEMPERATURE=0
```

⚠️ 但思考型模型大多忽略 temperature（上游 README 明确写了）。要用这个得换
非思考模型。

**减少辩论轮次**（已配）：

```ini
TRADINGAGENTS_MAX_DEBATE_ROUNDS=1
TRADINGAGENTS_MAX_RISK_ROUNDS=1
```

已经是 1 轮，没有再降空间。
