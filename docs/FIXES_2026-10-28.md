# 两个关键修复：涨停可成交性 + point-in-time 接入

> 2026-10-28 完成。这两个修复让 A 股回测的数字从"不可信"变成"可信"。

---

## 一、③ 涨停买不进 —— 可成交性过滤

### 问题

上游结算逻辑（`memory/settlement.py:fetch_returns`）把**决策日之后第一个交易日的
收盘价**当作入场价。对美股没问题，但 A 股有两条制度约束：

1. **±10% 涨跌停**（创业板/科创板 ±20%，ST ±5%）——涨停日该价格根本买不到
2. **T+1**——当日买入不能当日卖出

于是回测假设"以涨停价买入"，现实中排队都成交不了 → **alpha 系统性高估**。

### 解法

新增 `tradingagents/dataflows/vendors/akshare/fillability.py`，在结算时判断入场日
能否成交。判定为**不可成交**的三种情形：

| 情形 | 判据 |
|---|---|
| **一字涨停** | `high == low` 且涨幅 >= 阈值 → 全天封板 |
| **开盘涨停** | `open` 涨幅 >= 阈值 → 开盘就封 |
| **收盘涨停** | `close` 涨幅 >= 阈值 → 尾盘封板，收盘价买不到 |

涨跌停阈值按板块判定：

| 板块 | 代码前缀 | 阈值 |
|---|---|---|
| 主板 | 60 / 00 | 10% |
| 创业板 | 300 / 301 | 20% |
| 科创板 | 688 / 689 | 20% |
| ST | — | 5% |

### 接入点

`settlement.py:fetch_returns()` 新增 `check_fillability` 参数（默认 True）。
不可成交时返回全 `None`，该决策**保持 pending 不计入 alpha 统计**，并写 warning 日志。

**保守处理**：取数失败、停牌、非 A 股 → 返回 `unknown=True`，**不阻断结算**但记日志。
宁可标注也不假装确定。

### 数据源

三级回退（都实测可用）：

```
1. ak.stock_zh_a_hist     东财，字段最全（含涨跌幅）
2. ak.stock_zh_a_hist_tx  腾讯
3. ak.stock_zh_a_daily    新浪
```

每源 2 次重试（东财偶发 `ConnectionReset 10054`）。

## 二、① point-in-time —— 用巨潮公告日期补上游缺失信息

### 问题的真正形态

上游（`date_window.withhold_undated_statements`）对历史日期的处理是
**全给或全不给**：

> *"data is withheld for this date. This vendor dates a statement by the period it
> covers and reports no filing date, so it cannot show which figures were public
> on {as_of_date}."*

理由很正当：Yahoo 只标「覆盖期间」不标「公布日期」。结果是 A 股历史回测里
**基本面分析师完全空转**。

### 我们补什么

巨潮资讯（证监会指定披露平台）**每条公告天生带公告日期**。有了它就能回答上游
回答不了的问题：「某期财报是哪天公开的」。

于是可以做比"全给/全不给"更精细的事：

```
给定分析日期 as_of
  → 算出最近一期**已公布**的财报期
  → 把工具结果截断到那一期为止
```

### 关键实现：绕过上游的整份拦截

上游拿到历史日期就直接返回拦截文本，我们没机会截断。所以流程改成：

```python
_has_evidence, _period, _reason = _pit_evidence(ticker, _as_of)
if _has_evidence:
    _raw = route_to_vendor(method, ticker, freq, None)   # 拿全量
    _text = _pit_truncate(str(_raw), _period)            # 自己截断
    return _pit_notice(...) + "\n" + _text
return route_to_vendor(method, ticker, freq, _as_of)     # 无证据则走上游逻辑
```

### 判定规则（两级）

1. **法定披露截止日已过** → 该期必然公开（强保证，省一次网络请求）
   - 一季报 4-30、半年报 8-31、三季报 10-31、年报次年 4-30
2. 否则**查巨潮公告**，看有没有该期的定期报告公告

### 验证（决定性证据）

贵州茅台 2026 半年报的公告日是 **2026-08-15**：

```
分析日 2026-08-14  数据列含半年报 = False   ← 未公布，正确排除
分析日 2026-08-16  数据列含半年报 = True    ← 公告后，正确包含
分析日 2026-10-27  数据列含半年报 = True    ← 实时，正常包含
```

**同一个标的不同分析日期，可用财报期不同** —— 这就是 point-in-time。

### 覆盖范围

| 市场 | point-in-time | 说明 |
|---|---|---|
| **A 股** | ✅ 巨潮公告日期 | 本次新增 |
| 美股 | ✅ SEC EDGAR 申报日期 | 上游已有 |
| 港股 | ❌ 无依据 | 历史日期仍被上游整份拦截（**这是正确的**，我们无法证明何时公布） |

港股用今天日期正常（3913 chars）；历史日期被拦是应有行为。

## 四、还剩什么没解

| 问题 | 状态 |
|---|---|
| ② 样本量 | ⚠️ 成本问题不是正确性问题。1 单元格 ≈ 27 分钟，n=50 需一周 |
| ④ LLM 非确定性 | ❌ 品类固有限制，只能缓解不能根除 |

**现在 A 股回测的可信度**：

| 维度 | 可信度 |
|---|---|
| 技术面（`--analysts market`） | ✅ 可信（OHLCV + 可成交性过滤） |
| 基本面 | ✅ **现在可信**（point-in-time 已接） |
| 新闻/情绪 | ⚠️ A 股新闻走 AKShare 中文源，但无 point-in-time 约束 |

**唯一还缺的是新闻的 point-in-time**——新闻本身带发布时间，理论上也能过滤，
但上游没有这个机制，需要另外实现。
