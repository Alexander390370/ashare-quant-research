## 一、为什么要完善

**主人原话**：「就算是当过滤器，也得是完善的过滤器」

**旧版的三个硬伤：**

| 问题 | 表现 | 影响 |
|---|---|---|
| **只有指数成分股** | 800 只，剔除率 0.9% | 硬规则形同虚设 |
| **无行业/市值字段** | 只有代码+名称 | 无法做行业分散、分层 |
| **无财务因子** | 只有 6 个价量因子 | 无法做价值/质量风格 |
| **无深挖接口** | 筛选和深挖各自为政 | 链路不闭环 |

## 二、新增能力

### 1. 元数据模块（`screening/metadata.py`）

**数据源实测（2026-10-31，每项 4 次）：**

| 源 | 成功率 | 提供 |
|---|---|---|
| 深交所列表 | 4/4 | **行业 + 总股本 + 流通股本 + 上市日期** |
| 上交所主板 | 4/4 | 上市日期（**无行业**） |
| 上交所科创板 | 3/5 | 上市日期 |
| 全A代码名称 | 4/4 | 代码 + 名称 |
| 新浪全A快照 | 3/4 | 最新价（算市值用） |
| 东财行业板块 | **0/8** | 已弃用 |

**关键发现**：深交所列表自带「所属行业」（证监会分类）+「A股总股本」，这是免费的行業和市值来源。

**踩的坑**：股本字段是**带千分位逗号的字符串** `"19,405,918,198"`，`pd.to_numeric` 直接返回 NaN。必须先去掉逗号。

**产出**：
```
5223 只股票
  有行业：2905（深交所）
  有市值：2905
  市值范围：0 ~ 10269 亿
  中位市值：49 亿
```

### 3. 财务因子（`qlib_layer/financials.py`）

**数据源实测：**

| 源 | 成功率 | 提供 |
|---|---|---|
| **东财-财务分析指标** | **3/3** | ROE、EPS、BPS、净利率、负债率、周转率等 18 项 |
| **东财-个股指标** | **3/3** | 营收、净利润、同比增长率 |
| 同花顺-关键指标 | 3/3 | 80 项指标 |
| 东财-资产负债表 | 3/3 | 完整三表之一 |
| 东财-利润表 | **0/3** | SSLError |
| 东财-现金流表 | **0/3** | SSLError |

**可算的因子：**

| 类别 | 因子 |
|---|---|
| **质量** | `f_roe` 净资产收益率、`f_gross_margin` 毛利率、`f_net_margin` 净利率、`f_debt_ratio` 资产负债率 |
| **成长** | `f_revenue_yoy` 营收同比、`f_profit_yoy` 净利润同比 |
| **估值** | `f_pe` 市盈率、`f_pb` 市净率、`f_ps` 市销率 |
| **合成** | `f_quality`（ROE + 毛利率 - 负债率）、`f_growth`、`f_value` |

**踩的坑（严重）**：东财财务指标按日期**升序**排列，`iloc[0]` 是 2023-03-31（最老），`iloc[-1]` 才是 2026-09-30（最新）。

**如果不修，所有股票的财务数据都是 2023 年的，因子完全失效。**

### 4. 行业中性化（`qlib_layer/neutralize.py`）

**为什么必须做**：

```
银行股负债率 91-92%（天然如此）
制造业负债率 40-70%
-> 用「资产负债率 < 70%」会把整个银行业灭掉
```

**三种方法：**

| 方法 | 说明 | 适用 |
|---|---|---|
| `industry_zscore` | 行业内标准化（均值 0、标准差 1） | 通用 |
| `industry_rank` | 行业内分位（0-1） | 更稳健，不受极端值影响 |
| `neutralize_composite` | 分位/z-score 后加权合成 | 最终打分 |

**实测验证：**

```
原始数据：
  医药 ROE 均值 10.44
  电子 ROE 均值  9.22
  白酒 ROE 均值  9.12
  银行 ROE 均值  6.66  <- 系统性偏低

中性化后：
  医药 均值 -0.0  标准差 1.0
  电子 均值  0.0  标准差 1.0
  白酒 均值 -0.0  标准差 1.0
  银行 均值 -0.0  标准差 1.0  <- 行业差异被消除
```

### 5. 深挖桥接（`qlib_layer/bridge.py`）

**解决「筛选层和深挖层各自为政」的问题。**

**五种挑选规则：**

| 规则 | 说明 |
|---|---|
| `largest` | 市值最大的 N 只（最安全） |
| `smallest` | 市值最小的 N 只（弹性大） |
| `liquid` | 成交额最大的 N 只 |
| `random` | 随机 N 只（对照组） |
| `spread` | 按行业分散挑（每行业最多 1 只） |

**三种输出：**
- `bridge_<时间戳>.json`：完整记录（含状态说明）
- `picked_<时间戳>.csv`：挑出的名单
- 深挖结果自动回写

**关键设计**：记录里明确写

> 「深挖结论是「待验证假设」，不是「交易指令」。
> 六家评审明确指出：TradingAgents 是放大器，不是验证器。」

### 6. 全市场筛选（`screening/run_full.py`）

**新增规则（可配置开关）：**

| 规则 | 说明 |
|---|---|
| `exclude_st` | 排除 ST/退市 |
| `min_listing_months` | 上市 ≥ N 个月 |
| `min_avg_amount` | 日均成交额 ≥ N 元（绝对值） |
| `min_amount_percentile` | 日均成交额 ≥ 后 N% 分位 |
| `min_market_cap_percentile` | 市值 ≥ 后 N% 分位 |
| `exclude_suspended` | 排除停牌 |
| **`max_industry_weight`** | **单行业最多占 N%**（行业分散） |

**性能优化：**

| 优化 | 效果 |
|---|---|
| 日线窗口 3 年 → 90 天 | 数据量 -90% |
| 日线本地缓存（parquet） | 首次 30 分钟，之后增量 1-2 分钟 |
| 元数据缓存 24h | 不重复拉 |
| 财务数据缓存 72h | 不重复拉 |

**踩的坑**：上市时长用日线最早日期判断，但拉 3 年数据时「最早日期」= 窗口起点，所有股票都显示「35 个月」。

**修法**：用 `list_date` 字段（交易所列表自带），宁德时代 100 个月、美的 157 个月、比亚迪 184 个月。

| **经营现金流/净利润** | 现金流表 0/3 不可用 | ❌ 需换源 |
