## 一、三道防线

### 防线 1：方向断言（合成序列）

**原理**：用已知答案的合成序列验证因子语义。

| 测试 | 构造 | 期望 |
|---|---|---|
| mom20 方向 | 涨 20% / 跌 20% / 平坦 | 正 / 负 / 0 |
| mom20 精确性 | 构造恰好 +20% 的序列 | 因子 = +0.200000 |
| mom5 方向 | 涨 / 跌 | 正 / 负 |
| rev1 反转语义 | 涨 / 跌 | **负 / 正**（反转因子） |
| dev20 方向 | 涨 / 跌 | 正 / 负 |
| vol20 | 平坦序列 | 0 |

**这直接防住了 2026-10-30 那次 bug**——如果当时有这个断言，`Ref($close,20)/$close-1` 会立刻报错（涨 20% 算出 -13%）。

### 防线 2：三条不变量

**2a. 权重全取反 → 排名必须完全互补**

```python
normal = score_with(weights)
inverted = score_with({k: -v for k, v in weights.items()})
assert np.allclose(inverted, -normal)      # 分数取反
assert np.array_equal(rank_normal, rank_inverted[::-1])  # 排名互补
```

**如果权重反转后排名不变，说明权重根本没起作用，或因子值全是常数。**

**2b. 截断未来 → 历史因子不变**

```
构造：前 30 天固定 + 后 10 天两种完全不同的未来
验证：T=30 时点的因子值必须完全一致
```

**这防住前视偏差**——如果算 T 日因子时用了 T 日之后的数据，两种未来会算出不同结果。

**2c. 重跑两次 → 结果一致**

同一输入两次计算，必须完全一致。防随机性。

### 防线 3：独立复算

**原理**：用 pandas 直接复算，与 Qlib 从 `.bin` 读出的值比对。

```python
# Qlib 路径：.bin -> FileFeatureStorage -> D.features
qlib_closes = D.features(codes, ["$close"])["$close"]

# 独立路径：直接读 .bin 原始字节
raw = np.fromfile(bin_path, dtype="<f")
bin_closes = raw[1:]  # 第一个是起始索引

assert np.allclose(bin_closes, qlib_closes)  # 容差 1e-4
```

**抓三类错**：
- `.bin` 格式错（少了起始索引头）
- 列错位（open/close 混了）
- 日期错位（calendar 索引对不上）

## 四、踩到的坑：断言本身写错了

**第一次跑，`mom20 幅度` 失败：**

```
实际 +0.1299，期望 ≈ +0.20
```

**但这不是代码错，是断言写错了。**

我的合成序列是 `linspace(100, 120, 30)`，从第 1 天到第 30 天涨 20%。
但 `mom20` 用的是 `closes[-1]/closes[-21]`，即**第 10 天到第 30 天**——只有 +13%。

**修正**：
1. 断言改成 `expected = up[-1]/up[-21] - 1`（按真实语义）
2. 额外加一条「精确性」测试：构造 `[100×10, linspace(100,120,20)]`，这样 `closes[-21]` 恰好是 100，因子精确等于 0.20

**教训：断言写错也会误报。校验器本身需要被校验。**

## 六、还剩什么

**防线 1-3 覆盖了**：
- ✅ 因子方向语义错
- ✅ 权重失效
- ✅ 前视偏差
- ✅ 随机性
- ✅ `.bin` 格式错

**还没覆盖的**：
| 项 | 说明 |
|---|---|
| **数据源错** | 如果腾讯返回的数据本身就是错的（如停牌日填充），防线抓不到 |
| **因子选择错** | 防线只能验证"实现对不对"，不能验证"这个因子该不该用" |
| **权重合理性** | 权重是拍脑袋定的，防线不判断它是否合理 |

**这三条只能靠 ③ 回测验证。**
